GitHub 基本用法 · vibe coding 基本功

放在這裡是刻意的：剛才 ⑤ 他們聽了 8 個人講「我怎麼問的」，這一段就是把那 8 種做法收斂成幾條共通原則，接著馬上進團隊實作用出來。

A · 怎麼使用 GitHub（20 min）

  • 為什麼要用：專案有地方放、改壞了回得去、同事拿得到——最後這點正好是明天交換測試要的
  • 三個動作就夠：建一個 repo → 把資料夾放上去 → 改完再放一次。不講分支、不講 merge
  • 全部交給龍蝦：主機只登入主辦方一個帳號，作品放在 github.com/Arnold-leyan/ 底下、用英文名字開頭區分，學員不用登入；① 辦好的帳號會被邀請成協作者。各組今天就把專案 repo 建起來，明天交換測試直接給網址，不用傳檔案

B · vibe coding 基本功（20 min）

  • 先講結果，再講限制——說你要什麼、有什麼條件，不要教它怎麼做
  • 告訴它怎樣算做完——agent 會自己拆步驟、一口氣做完，你要講清楚的是終點（例：手機打得開、照片都有出現）
  • 卡住就換句話說，不要重複同一句——把「不行」換成「它剛做了 X，我要的是 Y」
  • 叫它先講計畫再動手——大改之前先看它打算怎麼做，省掉重來的成本
  • 一定要自己驗——它講得很順不代表是對的（早上 ③ 那張照片說明寫錯，就是這件事）

實作衝刺（一）：先把「AI 處理」那一格做到會跑

今天是個人專案，每個人做自己的。從你帶來的三件煩事挑一件，做成一個工作流優化。昨天分組做的那個不帶到今天，但昨天踩過的坑今天用得上。

先把話說清楚：一個工作流有五格，今天上午只做中間那一格。以「整理拜訪紀錄」為例——

五格這件事實際上是什麼今天怎麼辦
① 觸發每週五下班前要做這件事先手動——你自己記得
② 取得資料你口述 3 分鐘的拜訪內容先手動——自己錄好、自己貼進去
③ AI 處理把那段口述變成「客戶追蹤表＋下次要問的三件事」今天就做這一格
④ 產出一張可以直接用的表先手動——輸出複製出來就好
⑤ 交給誰存進共用資料夾給助理接手先手動——自己存

為什麼只做一格：①②④⑤ 手動做各只要一分鐘，③ 才是你每週真的花掉 40 分鐘的地方。一開始就想把五格全自動，兩小時後五格都做一半、沒有一格能用。

③ 那一格怎麼動手，五步：

  1. 準備一份真的樣本——你上週真的寫過的一份拜訪紀錄／一疊收據照片／一段逐字稿。不要用假資料，假資料看不出問題（客戶姓名先改代號）
  2. 跟 AI 講你要什麼結果——「把這段口述整理成一張表，欄位是：客戶、談了什麼、下一步、什麼時候跟進」。講結果和欄位，不要教它怎麼做
  3. 跑一次，看哪裡不對——不對的地方換句話說再跑：「它把 X 放到 Y 欄了，我要的是 Z」
  4. 對得上了，把那段話存成 SKILL（昨天 ② 學的），下次一句話就能再跑
  5. 換第二份樣本再跑一次——這才是完成 兩份不同的樣本都跑得對，才算「會跑」。只對一份通常是碰巧
  • 09:40 建 repo、準備樣本、開工（25 min）——題目在剛才那 10 分鐘已經挑好、拆好
  • 第 1 輪巡場（10:05）：③ 那一格跑得動了嗎？跑不動的當場把題目縮小——「整理一整年的拜訪紀錄」縮成「整理一份拜訪紀錄」，先讓它會跑再說
  • 第 2 輪巡場（10:30）：第二份樣本試了嗎？五格從頭到尾走一次通不通？手動的部分也算通
  • 第 3 輪巡場（11:05）：還在改的人收手了嗎？11:20 一定要停，剩下的時間要拿去寫文件——文件沒寫完，下午交換測試直接 0 分
