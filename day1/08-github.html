A · Setup 1只做一次

先教龍蝦：GitHub 小幫手

  1. 按右邊的「複製全文」
  2. 在 Telegram 貼給你的龍蝦
  3. 等它回「GitHub 小幫手已就緒」
  4. 傳 /new 開一個新對話

跟早上教 Skill Finder 一模一樣。

請幫我建立一個新的 skill：在你的 workspace 裡建立 skills/github-helper/SKILL.md，內容照下面這段一字不改。建好之後回覆我「GitHub 小幫手已就緒」。 --- name: github-helper description: 當使用者說「放上 GitHub」「再放一次」「回到上一版」「給我 GitHub 網址」時，用 git 和 gh 幫他管理自己的 repo。 --- # GitHub 小幫手 ## 每次開始前 1. 先確認 git 和 gh 都在：執行 `git --version` 和 `gh --version`。 - 這台主機由主辦方管理，git 和 gh 應該已經裝好。缺任何一個，不要自己安裝，告訴使用者「主機上還沒有 git／gh，請找主辦方」，然後停下來。 2. 執行 `gh auth status` 確認有沒有登入。還沒登入時： - 在背景執行 `gh auth login --web --git-protocol https`。 - 把畫面上的 8 碼代碼和網址 https://github.com/login/device 傳給使用者，請他自己在瀏覽器登入 GitHub、輸入代碼、按 Authorize，完成後跟你說。 - 絕對不要向使用者要密碼，也不要代替他登入。 - 使用者說好了，用 `gh auth status` 確認，再執行 `gh auth setup-git`，回報登入的帳號名稱。 - 已經登入時，先問使用者「現在登入的是 <帳號>，是你的嗎？」。不是他本人的帳號就停下來，不要用別人的帳號上傳。 3. `git config --global user.name` 是空的：用 `gh api user --jq .login` 和 `gh api user --jq .id` 取得帳號與 id，把 user.name 設成帳號，user.email 設成 `<id>+<帳號>@users.noreply.github.com`。 ## 放上去（新的 repo） 1. 確認資料夾路徑和 repo 名稱（英文小寫，用連字號，例：liming-office）。 2. 在資料夾裡建立 `.gitignore`，至少寫入 `.env`。 3. 安全檢查：列出要上傳的檔案。檔名或內容出現 .env、token、password、密碼、身分證、保單，就先停下來告訴使用者，不要上傳。 4. 用一句話告訴使用者：要上傳哪些檔案，以及「這會公開，任何人都看得到」。使用者說好之前，不要上傳。 5. `git init`（已經是 repo 就跳過）→ `git add -A` → `git commit -m "<一句話說明>"` → `gh repo create <名稱> --public --source . --push`。 6. 回覆 repo 網址（`gh repo view --json url --jq .url`）。 ## 再放一次 1. 到同一個資料夾，用 `git status` 看改了哪些檔案，列給使用者。 2. 做同樣的安全檢查。 3. `git add -A` → `git commit -m "<使用者說的這次改了什麼>"` → `git push`。 ## 回到上一版 1. 用 `git log --oneline -5` 列出最近幾版，用白話說明每一版改了什麼。 2. 使用者選好要回到哪一版後，用 `git revert --no-edit <那一版>..HEAD`，再 `git push`。保留紀錄，不要用 reset。 ## 絕對不做 - 不刪除任何 repo，不動使用者沒指定的 repo，不把 private 改成 public。 - 不在對話裡顯示 token。 - 不用 `git push --force`。
小幫手規定龍蝦：上傳前先列檔案、等你說好；不上傳 .env 和客戶資料；不刪 repo、不 force push。原始檔在工作坊資料夾 skills/github-helper/。

A · Setup 2只做一次

登入 GitHub：龍蝦給代碼，你自己登入

  1. 對龍蝦說「幫我登入 GitHub」
  2. 它傳來一個網址和一組 8 碼代碼
  3. 在瀏覽器打開網址，自己登入、貼代碼、按 Authorize
  4. 回 Telegram 說「好了」

密碼只在 GitHub 網頁上輸入，不傳給龍蝦。

龍蝦示意

幫我登入 GitHub

請打開 github.com/login/device，登入後輸入這組代碼：ABCD-1234。完成後跟我說。

這是龍蝦連上的第二個帳號。gh 預設登入權限是 repo、read:org、gist，只能管你的 repo，沒有刪除 repo 的權限，正好是資安課講的最小權限。代碼 15 分鐘內有效，畫面上的代碼是示意。

A · Before upload剛剛資安課講的

Public，
就是公開。

龍蝦列出檔案清單時，看一眼裡面有什麼。

這三種東西，一個都不能放上去：

.env任何 token客戶資料
接資安課第二條「金鑰只放 .env，不放上 GitHub」。小幫手會自動把 .env 排除在外，但客戶資料它不一定認得出來，最後一關是人。放錯了不能只是刪檔，舊版本還查得到：token 要立刻到 BotFather 換一把。

改了 1 個檔案：index.html。已經放上去了。

那一句「這次改了什麼」，就是這一版的名字。

改壞了

剛剛那版改壞了，幫我回到上一版

最近三版是：……要回到哪一版？

每一版都留著，回得去，所以可以放心讓 AI 大膽改。

「改壞了回得去」是 vibe coding 的安全網。小幫手用的是保留紀錄的回復方式（10/8 已在本機測過），舊版本不會消失。對話內容是示意。

五個習慣後半段

15:30 – 15:50二十分鐘

vibe coding 基本功

剛剛 ⑤ 八個人講了「我怎麼問的」。
把大家都用得上的，收成五條。

每一條都用「這樣講 → 改成這樣」對照，盡量引用 ⑤ 裡學員真的講過的例子。

Habit 1五個習慣

先講結果，再講限制

✗ 教它怎麼做

先用 HTML 做一個框，裡面放標題，再加一個 CSS 讓它置中……

✓ 說你要什麼

我要一頁介紹黎明辦公室的網頁，手機看也要正常，三段以內

說要什麼、有什麼條件。怎麼做，交給它。

非工程背景的人反而常犯左邊的錯：以為要講得很技術。不用，講結果和條件就好。

Habit 2五個習慣

告訴它怎樣算做完

✗ 只說要做什麼

幫我做一個黎明辦公室的網頁

✓ 連終點一起說

幫我做一個黎明辦公室的網頁。做完要：手機打得開、7 張照片都有出現、錯字自己檢查一遍，然後放上 GitHub 給我網址

Agent 會自己拆步驟、一口氣做完。你要講清楚的是終點。

現在的 agent 不用一小步一小步餵，一次交代整件事它會自己規劃、做完。真正會出問題的是沒說「怎樣算做完」：它會停在它覺得夠了的地方。驗收條件講清楚，它也能自己檢查。

Habit 3五個習慣

卡住就換句話說

✗ 重複同一句

不對，再做一次

還是不對，再做一次

✓ 說它做了什麼、你要什麼

你把照片放在最上面，我要的是放在第二段下面

公式：「它做了 X，我要的是 Y」。

這條幾乎每個人在 ⑤ 都講到了。把它變成一句可以背的公式。

Habit 4五個習慣

大改之前，先叫它講計畫

要改很多地方、或要刪東西之前，先看它打算怎麼做。

計畫不對，這時候改最便宜。

龍蝦例句

我想把整個網頁改成兩種語言。先告訴我你打算怎麼改，我說好再動手

我打算：一、……二、……三、……可以嗎？

第二點不要，其他可以

這也是資安課「權限提示是煞車」的延伸：讓它先說，你再決定。

Habit 5五個習慣

一定要，
自己驗。

早上 ③ 那張照片，龍蝦寫的說明講得很順，但是錯的。

數字、名字、日期，用之前自己對一次。

它講得很順，不代表是對的。

學員的工作都碰得到客戶資料和數字，這條最要緊。明天交換測試，別人會實際跑你的東西，驗沒驗過一跑就知道。

On the wall貼上牆

五個習慣

  1. 1先講結果，再講限制
  2. 2告訴它怎樣算做完
  3. 3卡住就換句話說：它做了 X，我要的是 Y
  4. 4大改之前，先叫它講計畫
  5. 5一定要自己驗
這五條做成海報上牆，跟資安三條放在一起。接下來的團隊實作和明天的個人專案都會用到。
